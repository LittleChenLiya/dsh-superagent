dsh-superagent · DeepSeek Harness 插件

一个目标进去，模型拆成并行子任务，一份报告出来。

dsh-superagent 给 DeepSeek Harness 补上"长时任务"这一段：一次调用拿到目标， 由模型规划成互不依赖的子任务，默认三个子代理同时跑，结果合并成一份报告。 run 的状态和花销写在磁盘上，宿主进程被杀掉之后还能接着跑。

Node ≥ 24.9.0 dsh ≥ 0.2.2-rc.1 < 0.3.0 零运行时依赖 MIT 许可 个人项目，与 DeepSeek 无关

01它解决的两个具体问题

宿主一断，run 全丢

单个 agent loop 是一个上下文、一个序列。目标需要几条独立的工作线时，它只能排队做； 进程崩掉或重启，这一轮没有留下任何可以接着跑的东西，只能从头再付一次钱。

花销看不见

子代理的调用、缓存命中的比例、一次 run 到底花了几次调用，默认没有任何账本。 等账单出来才知道哪个目标烧得多，那时已经烧完了。

02三件核心能力

多任务并行调度

planner → N workers → aggregator

一次规划模型调用把目标拆成互不依赖的子任务，按 maxParallel（默认 4，硬上限 8）并发跑， 最后合并。子代理之间上下文隔离，只把结果交回来，所以一次 run 的上下文不会随子任务数量线性膨胀。

  • 没有依赖图：planner 只产出互不依赖的叶子任务。有先后关系的工作要自己串在一个子任务里。
  • 规划是一次模型调用；回复解析不出子任务时，整条 run 降级成单个子任务并标记 plan.mode = "degraded"。
  • 同一个目标在同一个会话里重复发起，返回已有 run id 并标记 deduped: true，不重复付规划费。

中断可续

interrupted → resume

每条 run 一个 JSON 文件，临时文件加重命名写入；谁是 owner 由本地 pid、心跳和文件锁判断， 而不是靠进程自己的记忆。重启后 superagent_status 报 interrupted 并给出判定依据， superagent_resume 只补没完成的部分，规划结果直接复用。

  • 只有"没有活着的 owner"的 run 才会被标成 interrupted：本地死 pid 直接回收，共享目录按 90 秒心跳判断。
  • 跨进程取消走 .cancel 标记文件，不依赖 socket；实测对一个忽略 abort 的子任务，取消 1.99 秒返回。
  • resume 会重建预算上限、保留已花掉的部分——把上限调高再 resume，就是"继续"而不是"重来"。

成本与调用可追

usage · cost · budget

每条 run 结束都打印实测的输入、输出、缓存命中 token 与调用次数，另加两个硬预算： maxModelCallsPerRun 与 maxTokensPerRun。预算在每次 spawn 之前检查， 触顶后不再起新子代理，正在跑的那个被 abort，已完成的报告仍然合并。 

usage: input 1882 (+19456 prompt tokens served from cache), output 7363, calls 3
cost: ¥0.1016 (estimate; all models priced)

上面是一次真实付费 run 的原样输出（3 次调用，按运维自己填的 DashScope 峰时价计算）。 插件不自带任何模型价格：没配价格时打印 not computed，只有部分模型有价格时打印 at least …，总价永远按下界报，不编一个 0。

  • token 数来自子会话日志的实测求和，有一个独立脚本逐条核对过，与插件打印一致。
  • 日志读不到时不算沉默：打印 usage note: 说明是下界；调用次数预算照常生效。
  • 运维侧还有两个只读工具，读同一批 run 文件、不依赖会话：终端里的 watch 面板，和一份自包含的 HTML 报告（内联 CSS 与 SVG，无脚本、无网络请求）。

03安装

dsh plugin --profile web add @xiangyixie/dsh-superagent@0.9.3

行里的版本号只是本页写作时的值，以 README 的固定安装行为准。 必须写版本号：不写时 pnpm 的最小发布年龄策略会跳过刚发布的版本，装到一个旧的却报告成功。 不要 npm i -g dsh——npm 上的 dsh 是另一个包。

装完用 dsh --profile web --dump-config 确认有下面两行，否则插件装了但没挂载，工具不会存在：

- id: superagent
  name: @xiangyixie/dsh-superagent

从零跑通第一个任务的分步操作在 quickstart.md。

04什么时候别装

这些情况下，它只会让你多付一次规划费和合并费

一次模型调用就能答 你付的是一个 planner 加一个 aggregator，外加每层各自的上下文。问题本身很小的时候，这层编排是纯开销。
必须在一个 turn 内结束 run 是后台推进的。wait_seconds 用完就返回 next: superagent_status …，不会为了等它结束而阻塞整个会话。
中间需要人工审批 没有中途暂停等确认的通道。子任务可以留一条 attention 提问，但那是在 run 结束前后送达，不是审批门。
需要多级委派 子代理深度固定为 1，worker 不能再开 worker。这是宿主强制执行的，不是提示词约束。
想要宿主内的面板或仪表盘 插件不加 UI、不改宿主代码，对外只有 superagent_* 工具。面板是另一个终端里的只读工具，不是产品界面。
需要隔离或沙箱 子代理用宿主自己的凭据和文件系统，受宿主沙箱策略约束。这不是安全边界。
