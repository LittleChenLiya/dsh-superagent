# Real-host end-to-end, 2026-11-14

This is the first time the plugin was exercised end-to-end against a real
`dsh@0.2.2-rc.1` host instead of the fake spawner used by `npm test`. It found
four defects that the offline suite could not see; all four are fixed in this
record's commit.

## What is real and what is stubbed

Real:

- The host binary: `@deepseek-ai/dsh@0.2.2-rc.1` on Node `v24.14.1`.
- The host's `subagents` / `subagent-spawn-in-process` services, the real
  `agents` registry, real child sessions, real zstd session logs under
  `$DSH_HOME/sessions`, the real tool registry, the real headless app.
- The plugin installed from its own `npm pack` tarball, exactly as a stranger
  would install it.
- Run state, recovery, cancel markers, locks, usage accounting, pricing, notify.

Stubbed:

- The model route. The build machine has **no** `DEEPSEEK_API_KEY` (or any
  provider key), so a paid run is impossible here — it fails verbatim with
  `MISSING_CREDENTIAL: llm-deepseek: no API key for provider route
  "deepseek-official"`. A local Cordis plugin
  ([docs/e2e/stub-llm](stub-llm)) registers the route `e2e-stub` and streams
  deterministic chunks with fixed usage numbers. It is not published (`files`
  in `package.json` is an allowlist of 10 files) and the host cannot tell it
  apart from any other provider.

Consequence: the *token counts and cost* below are synthetic, but they travel
through the real pipeline — the stub reports them, the host writes them into
each child's session log, and the plugin reads those logs back. The point of
`verify-usage.mjs` is that the plugin's number equals an independent sum of the
logs. A real model would change the numbers, not the path.

## Defects this run found, and the fixes

1. **A graceful host shutdown settled a resumable run as `failed`.**
   In a one-shot headless turn, the host exits when the turn ends. The
   `subagents` service vanishes, every in-flight child throws "subagent
   service is unavailable", the plugin counted that as a failed attempt, burned
   the retries, and wrote `failed`. `superagent_resume` then had nothing
   resumable. Fixed: the spawn error carries `code: 'subagent-unavailable'`;
   the orchestrator marks `host-gone`, clears the attempt error, aborts the
   remaining children, leaves unfinished subtasks `pending`, and settles
   `interrupted`.
2. **A dead local pid was ignored for up to 90 s.** `ownership()` checked the
   heartbeat first, so `kill -9` left the run `running` even though the pid was
   gone on the same machine. Fixed: when the run was written by this machine,
   a dead pid outranks a fresh heartbeat; a run from another machine on a
   shared directory still trusts the heartbeat. The reclaim basis is printed.
3. **A reclaimed run said its cost was unknown.** Recovery rewrote the status
   but never republished `usage`/`cost`, so a run that had already spent tokens
   printed "cost: not computed". Fixed: reclaim sums `usageByChild` and
   recomputes the cost.
4. **Per-subtask usage was `null` after a normal run.** The read at child
   completion raced the log flush; the run total was right, the per-subtask
   number was missing. Fixed: settle writes the final per-child snapshot back
   onto each subtask.

Also fixed while here: the plugin no longer ships a `qwen-flash` price (the
README already said it ships none), and the config docs no longer imply
otherwise.

## Second pass: the embedding surface (same day)

A later round added the opt-in HTTP control plane (`controlPort`) and re-ran the
same install with that key set to `0`. Method unchanged: real
`dsh@0.2.2-rc.1`, real subagents, the keyless stub route. Transcript:
[transcripts/control-plane.log](e2e/transcripts/control-plane.log).

- **17/17 checks passed.** Route index, health, 401 without a token and with a
  wrong token, 409 `no-session` for a missing and for a closed session,
  `POST /runs` → 202, `GET /runs/:id?wait=60` → `completed` with a report and
  measured usage, the run appears in `GET /runs`, cancel on a terminal run says
  "nothing to cancel", resume returns it unchanged, unknown run → 404, missing
  token → 401.
- The run created over HTTP (`20261114T082625-d8c8`) is an ordinary run: the
  same `parentSessionId`, the same measured usage, the same `text` the tool
  would print.
- After the host exits, `control.json` is gone and the port is closed; the
  discovery file is written only after the listener is up, so an embedder never
  reads a URL that is not answering.
- Two harness facts worth remembering: root session directories are named
  `session-<uuid>` (child directories use the bare uuid), and the discovery
  file is UTF-8 without a BOM — Windows PowerShell 5.1 needs `-Encoding UTF8`.

### Cross-process cancel over HTTP

Two headless hosts ran at the same time against one state directory
(`C:\Windows\TEMP\dsh-e2e2-home\state\superagent`), each with `controlPort: 0`
and therefore its own discovery file. Host A started a run; host B mounted
afterwards, saw the run, and cancelled it through B's control plane. Transcript:
[transcripts/cross-cancel.log](e2e/transcripts/cross-cancel.log), 9/9 checks.

- The two control planes are different processes with different ports and
  tokens (`9768` / `29604` in the run shown).
- **B's mount did not reclaim A's run.** B logged
  `run … is still owned (owner pid 9768 is still running); leaving it running`
  and reported the run as still active, not `interrupted`.
- `POST /runs/:id/cancel` on B returned 200 immediately; both hosts converged on
  `cancelled`, and A's workers logged `threw: aborted`.
- The user-facing text for that run carries no `error:` or `hint:` line, even
  though the owner stores `cancelled by superagent_cancel` as an audit note.
- `control.json` was gone after both hosts exited.
